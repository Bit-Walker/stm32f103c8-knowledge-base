## 2.5 中断屏蔽寄存器

| 寄存器 | 有效字段 | 功能 | 关键边界 |
|---|---|---|---|
| PRIMASK | bit 0 | 为 1 时阻止所有可配置优先级异常激活 | 不屏蔽 NMI、HardFault |
| FAULTMASK | bit 0 | 为 1 时阻止除 NMI 外的异常激活 | 能屏蔽 HardFault；风险高，不宜作为一般临界区工具 |
| BASEPRI | 组优先级阈值 | 非零时按 PRIGROUP 去掉子优先级部分，阻止相同或更低组优先级异常激活 | 值 0 表示不设置此屏蔽；数值越小紧急程度越高 |

F103 实现四个优先级位，写入优先级字节时有效值位于高四位，低四位未实现。直接写 BASEPRI 与使用 CMSIS 的逻辑优先级参数时，必须确认是否已经完成左移编码。

BASEPRI 不能在同一抢占组内按子优先级选择性放行。

例如，PRIGROUP=5 时，C8 高四位分为2位组、2位子；写 BASEPRI=0x50 后，有效组阈值为0x40，所以编码0x40和0x50的中断都会被屏蔽。建议阈值的子优先级位写0，避免误读。

只有当前执行优先级数值大于−1时才能置 FAULTMASK=1，不能在 NMI/HardFault 中靠它进一步提升屏蔽。[Arm DDI0403E.b §B1.5.4，B1-584～585](../来源/Arm_DDI0403Eb.md#src-armv7m-eb-mask)

FAULTMASK 通常在异常返回时自动清除，从 NMI 返回的情况例外。临界区应保存进入前的屏蔽状态，并在退出时恢复，避免无条件开中断破坏外层临界区。


来源：[PM0056 §2.1.3 Core registers；§3.9.2；§3.9.6–3.9.7](../来源/PM0056.md#src-pm0056-r7-mask)；[ARM DDI0403E.b §B1.5.4 Exception priorities and preemption，pB1-583,B1-584,B1-585](../来源/Arm_DDI0403Eb.md#src-armv7m-eb-mask)。

## 3.2 内存类型与访问顺序

Normal 内存允许处理器为效率进行一定的访问重排或提前访问。Device 用于有副作用的寄存器，访问约束更严格，但写入可能经过缓冲。Strongly-ordered 的访问顺序和完成约束更强，写入不采用普通的缓冲语义。

下表表示原文给出的顺序关系。“保证”表示前一访问与后一访问受该类型组合约束保持顺序；“未保证”不能作为设备协议的顺序依据。

| 前一访问类型 / 后一访问类型 | Normal | Device，不共享 | Device，共享 | Strongly-ordered |
|---|---|---|---|---|
| Normal | 未保证 | 未保证 | 未保证 | 未保证 |
| Device，不共享 | 未保证 | 保证 | 未保证 | 保证 |
| Device，共享 | 未保证 | 未保证 | 保证 | 保证 |
| Strongly-ordered | 未保证 | 保证 | 保证 | 保证 |

**表格核对：**原 PDF 第25页表11的 Strongly-ordered→Normal 一格为“−”，即未保证；不能把该页对 Strongly-ordered 的概括句扩大成所有类型组合都自动有序。表中任一“未保证”组合若承载同步协议，仍须使用适当屏障。

volatile 约束编译器对访问的处理，不能代替处理器内存屏障，也不能让多次访问成为一个原子事务。

## 3.3 三种屏障

| 指令 | 保证的重点 | 常见用途 |
|---|---|---|
| DMB（Data Memory Barrier） | 屏障前后的显式内存访问按要求排序 | 发布共享数据后置标志、交接信号量、修改向量后开放使用 |
| DSB（Data Synchronization Barrier） | 等待先前显式内存访问及相关操作完成，再继续后续指令 | 改变影响执行的系统配置、进入要求写操作完成的状态 |
| ISB（Instruction Synchronization Barrier） | 刷新后续取指和执行上下文 | 修改 CONTROL、执行环境或代码后，使后续指令看到新状态 |

原 §2.2.4 的五项具体用法为：

- 改向量项后、使能相应异常前插入 DMB，确保新向量先可见。
- 自修改代码后插入 ISB；若写入尚未完成，还应结合适当 DSB 完成写入与取指同步。
- 切换存储器映射后使用 DSB。
- 对已挂起或激活异常动态修改优先级后使用 DSB，确保修改生效。
- 多主设备信号量操作后使用 DMB，使共享数据访问按协议对其他主设备可见。

原文说对 Strongly-ordered 区（例如 SCB）的访问本身不要求额外 DMB；这不免除某一系统配置操作另外规定的 DSB/ISB。内存映射、异常优先级等系统改变需要按相应寄存器说明使用 DSB/ISB。自修改代码需要处理代码写入和取指之间的同步。处理器没有数据缓存也不意味着可以省略所有屏障。


来源：[PM0056 §2.2.4；§3.9.3–3.9.5](../来源/PM0056.md#src-pm0056-r7-barriers)。

## 6.4 异常进入与栈帧

[Arm DDI0337E §5.5.1 Figure5-1](../来源/Arm_DDI0337E.md#src-ddi0337e-stack-layout)给出下列栈布局；地址顺序不是压栈总线事务时间先后。

异常进入时，硬件把 R0、R1、R2、R3、R12、LR、返回 PC、xPSR 共八个字保存到异常发生前正在使用的堆栈。按压栈后 SP 起算的地址顺序如下：

| 偏移 | 保存值 |
|---|---|
| +0x00 | R0 |
| +0x04 | R1 |
| +0x08 | R2 |
| +0x0C | R3 |
| +0x10 | R12 |
| +0x14 | LR |
| +0x18 | 返回 PC |
| +0x1C | xPSR |

CCR.STKALIGN 控制异常栈帧的对齐要求。为满足对齐可能存在附加填充，恢复时由硬件结合保存状态处理；故障处理代码不能在未判定布局时假定调用者 SP 恰好增加 32 字节即可还原。

进入 Handler 后活动栈切换为 MSP。若被中断的 Thread 使用 PSP，硬件帧仍在 PSP 上；故障入口需要依据 LR 的 EXC_RETURN 判定应读取哪一个栈。R4～R11 不属于这八字自动帧，普通编译器函数和 RTOS 负责按调用约定保存所需寄存器。

异步异常请求到达与进入处理程序之间存在响应过程，不应以为触发后当前程序一条指令都不可能继续执行。

## 6.5 尾链与晚到异常

若异常返回时已有满足激活条件的挂起异常，处理器可以进行尾链：跳过不必要的完整出栈和再次压栈，直接转入下一处理程序。

若处理器正在为一个异常执行进入压栈，而此时更高优先级异常到达，可以先服务晚到的高优先级异常；原来的较低优先级异常保持等待。软件不应依赖触发先后顺序替代优先级仲裁。

## 6.6 EXC_RETURN

Handler 中 LR 通常保存特殊返回值。将有效 EXC_RETURN 装入 PC 时，处理器按照编码执行异常返回，恢复硬件栈帧。

| EXC_RETURN | 返回目标 | 恢复帧使用的堆栈 |
|---|---|---|
| 0xFFFFFFF1 | Handler | MSP |
| 0xFFFFFFF9 | Thread | MSP |
| 0xFFFFFFFD | Thread | PSP |

其他不符合本内核规则的编码不能当作合法异常返回值。BX、合适的 POP、LDR/LDM 装载 PC 等可以触发返回识别，但必须处于合法异常上下文并保持栈内容有效。破坏 LR、返回 PC、xPSR 或活动异常状态可能触发 UsageFault/HardFault。

来源：[PM0056 §2.1.1–2.1.3；§2.3.7](../来源/PM0056.md#src-pm0056-r7-exception-frame)。
