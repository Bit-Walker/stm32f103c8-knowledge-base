# HAL 开发参考入口

HAL（Hardware Abstraction Layer，硬件抽象层）的开发资料按初始化、中断接入、外设调用和错误处理组织。需要查某个接口时，可直接进入对应外设页面。

## 官方资料与版本

- [UM1850 Rev3](../来源/UM1850.md#src-um1850-r3-hal-common-model)：HAL 通用模型、接口类别、MSP、时基与参数断言。
- [UM1847 Rev3](../来源/UM1847.md)：CubeF1 工程组织与 HAL 接入。
- [AN4724 Rev2](../来源/AN4724.md)：官方示例分类及运行环境边界。
- [固定驱动实现](../来源/驱动实现.md)：具体 API 的返回分支、状态变化、缓冲区访问及版本差异。

查阅时同时记录手册修订号与工程采用的驱动版本；源码结论按对应页面的固定提交核对。

## 通用接口与扩展接口

UM1850 §3.6–3.7（pp20–21）按初始化/反初始化、I/O、控制、状态/错误组织通用 API；TIM 等模块还按 PWM、输出比较、输入捕获等功能分类。扩展接口常位于 `_ex.c/.h`，使用 `HAL_PPPEx_Function` 命名，例如 `HAL_ADCEx_Calibration_Start`。

`PPP` 是手册中的外设占位符。实际函数名、返回类型及参数以对应头文件为准；不能把通用模型中的示意名称直接作为可编译声明。扩展接口的适用芯片与实例也需要核对。

[GPIO 与 EXTI 的 HAL 调用边界](../参数/HAL_GPIO与EXTI调用边界.md)：初始化字段、旧 EXTI 配置、共享 IRQ 掩码以及读写和翻转的并发条件。

## 初始化与中断接入

MSP（MCU Support Package）初始化处理外设所需的 RCC、GPIO、NVIC 和 DMA 等底层资源。UM1850 §3.12.2.3（pp32–33）说明默认 MSP 回调为 weak 实现，由应用提供所需实现；各外设 Init 在什么状态下调用 MSP，需结合固定源码。

UM1847 §4.2.1（pp18–20）将工程配置、HAL 启动、时钟配置、MSP、外设/DMA 中断分发和回调纳入接入过程。仅启用 NVIC 不能证明中断已分发给正确句柄。

## 时基、断言与错误处理

[HAL 毫秒计数与阻塞延时](../参数/HAL毫秒计数与阻塞延时.md)：默认 HAL_Delay 返回条件、零延时、32 位补偿加法及 HAL_MAX_DELAY 的函数边界。

[官方 TIM2 时基示例的调用链、分频与移植边界](../参数/HAL定时器时基与官方示例边界.md)：包含多定时器回调、暂停/恢复、tick 配置与初始化返回值条件。

UM1850 p32 说明默认时基下 `HAL_Delay` 依赖 SysTick ISR 更新的软件计数。在外设 ISR 中等待时，时基中断必须能够抢占该 ISR；优先级与屏蔽条件应一起核对。替换时基后按实际实现检查，不能继续假设 SysTick 提供计数。

UM1850 §3.12.4.3（pp38–39）给出参数断言机制：启用 `USE_FULL_ASSERT` 时，条件失败调用应用的 `assert_failed`；未启用时，所示 `assert_param` 展开为 `(void)0`。断言并不等同于 API 返回 `HAL_ERROR`，也不保证覆盖所有非法参数。具体检查项、返回值、错误码与失败后的状态，以固定源码为依据。

## 官方示例的使用边界

AN4724 §2（pp4–5）区分 HAL/BSP 的 `Examples`、LL 的 `Examples_LL` 和混合的 `Examples_MIX`。示例 `readme` 提供运行条件；文档明确指出，更换编译器或板卡环境后不保证直接正常运行。引用示例时需保留版本与板卡条件，再核对工程的引脚、时钟、容量和外设资源。

手册示意与实际实现的差异保留在[UM1850 来源记录](../来源/UM1850.md#src-um1850-r3-hal-common-model)。各主题分别注明资料核查和板端验证状态。
